# 平台概念与运行逻辑

本导览帮助第一次接触 Web Presentation 的智能体建立执行任务所需的最小心智模型。读完后，应能把“生成一套演示”“增加一页”“统一视觉”“替换素材”等自然语言目标映射到平台对象和运行闭环，而不是把任务误解为生成本地 PPTX、HTML 或普通 Vue 项目。

## 一句话理解

Web Presentation 是把演示内容代码化、把设计能力资产化、把渲染校验平台化的 AI 创作系统。

- **内容代码化**：每个页面的主体内容是一份完整 Vue 3 SFC，由 Backend 持久化和版本管理。
- **设计资产化**：组件、资源、主题、样式和字体在工作空间内共享，页面引用真实资产，不把所有内容复制进单页代码。
- **渲染平台化**：Runtime 按项目配置在固定尺寸画布中编译、渲染和诊断页面；截图是实际视觉结果的证据。
- **操作受控化**：外部智能体只通过 `wp` CLI 和公开 API 操作，Backend 负责权限、归属、版本、依赖、校验和异步任务。

因此，智能体的主要成果通常是 Backend 中新增或更新的项目、页面、路由与共享资产。本地 `.vue`、`.json` 和截图文件只是提交候选内容、复杂参数或查看结果的临时载体。

## 从用户目标到可见页面

```text
用户的内容与视觉目标
        ↓
选择工作空间（权限和共享资产边界）
        ↓
确定项目（画布、主题、基础字号、样式规范）
        ↓
规划页面与路由（内容页、顺序、分组和可见性）
        ↓
页面 Vue SFC（引用已发布组件、真实资源和 Runtime Kit）
        ↓
Backend Mutation Job（权限、版本、编译、渲染、布局校验）
        ↓
Runtime 固定画布结果
        ↓
读取最新版本
        ↓
按需获取短期预览地址并截图复核，必要时局部修正
```

这条链路决定了操作顺序：先读上下文和配置，再构图和写源码；先等写入任务成功，再用截图评价视觉结果。不能只生成一份看似合理的 Vue 文件便声称页面已经完成。

## 四个系统角色

| 角色 | 作用 | 外部智能体如何对待 |
| --- | --- | --- |
| Editor | 用户管理和编辑内容的创作工作台 | 用户可在这里查看项目、页面、资产和预览；CLI 不操控 Editor UI |
| Backend | 权限、对象、版本、契约、任务和构建产物的事实源 | 所有查询和写入结果以 Backend 返回为准 |
| Runtime | 编译 Vue SFC、加载公开能力、固定画布渲染、诊断和截图 | 不直接访问；由 Backend 任务调度 |
| `wp` CLI | 外部智能体访问平台的公开入口 | 用它发现对象、读取规范、提交变更、等待任务和获取截图 |

智能体不直接访问平台数据库、Redis、Runtime、Chromium 或内部 Service，也不在本地启动一个替代平台的 Vue/Vite 项目。

## 对象分层

### 工作空间：最外层边界

工作空间同时是权限边界和共享资产边界。PAT 只允许访问获授权的工作空间；不同空间的页面、组件和资源不能互相引用。执行任何写入前都要知道当前工作空间，不能仅凭同名项目或资源猜归属。

### 项目：一组演示内容的容器

项目通常对应一套演示、报告、图文卡片集合或专题内容，包含三类关键数据：

- `configuration`：画布宽高、基础字号、主题、样式规范和建议组件等当前快照；
- 页面：每一页的元数据、Vue SFC、版本、依赖和截图信息；
- 路由树：页面顺序、分组、路径和可见性。

页面归属项目不等于页面已经出现在正确路由位置。创建、移除或重排页面时，应按任务检查路由树是否也需要调整。

### 工作空间资产：可复用的设计能力

- **组件**：可发布、可版本化的 Vue 代码资产。页面组件承载整页或重复页面骨架，内容/原子组件承载稳定区块。
- **资源**：图片、视频、三维模型（自包含 GLB）、图标、SVG、Draw.io、Mermaid、Chart、Formula、字体等，通过真实逻辑名和对应 Runtime 组件引用。三维模型使用 `AssetModel`，替换文件会同步更新当前与历史页面预览。
- **主题**：共享色彩语义；页面优先使用主题 token，而不是逐页硬编码品牌色。
- **样式**：可复用的项目配置模板；应用后成为项目自己的快照，不持续继承模板变化。
- **字体**：工作空间注册并由平台下发的字体能力。

这些资产在写页面之前就是输入。多页一致性通常来自项目配置、主题和页面组件，而不是让智能体分别复制相同样式到每一页。

### Runtime Kit：平台公开运行时能力

Runtime Kit 提供页面容器、资源渲染、主题、页码、路由目录等版本化公共能力。它不是任意前端组件库，也不是工作空间资产。只能使用 `wp runtime-kit list/get` 返回的真实、带 `.vN` 的 import path，不能按经验猜路径或引用 Runtime 私有模块。

### Mutation Job：重任务的执行记录

页面/组件创建与源码修改需要编译、渲染和布局检查，因此由持久化 Mutation Job 执行。命令返回 Job 不等于完成；只有 Job 进入 `succeeded`，并能重新读取到预期对象版本，才代表平台写入成功。

更细的字段、归属、快照和依赖区别见 [平台资源模型](./platform-model.md)。

## 把常见任务映射到平台

| 用户表达 | 主要对象与动作 | 开始前必须读取 |
| --- | --- | --- |
| “生成一套新的演示” | 目标工作空间；新建或确认项目；配置；多张页面；路由顺序；必要共享资产 | 工作空间能力、项目/配置、可复用组件、资源、主题/样式、页面 standards |
| “给这个项目增加一页” | 创建页面，并根据期望位置检查或更新路由 | 项目配置、当前页面列表、路由、建议组件和资源 |
| “修改/重做这一页” | 基于最新页面版本读取源码、依赖，提交候选或结构化 edits | 页面详情、最新源码、当前版本、项目配置、页面 standards |
| “让整套页面风格一致” | 优先检查项目配置、主题和页面组件，再决定是否局部改页 | 配置快照、主题、样式、已发布页面组件、现有页面 |
| “替换图片/图标/三维模型/字体” | 查询或创建工作空间资源；三维模型按 ID 和 `file_hash` 基线替换，再检查引用它的页面或组件 | 真实资源 name/ID、render type、当前 file_hash、依赖和目标源码 |
| “做一个以后能复用的版式” | 创建或修改页面组件，维护 preview schema，并发布稳定版本 | 组件 standards、现有组件、草稿/发布版本、依赖 |
| “看看效果/获取交互链接” | 对已有成功版本获取项目或页面短期预览地址，必要时再截图 | 目标项目/页面 ID、最新版本与预览响应 |
| “只评估怎么做” | 只读查询并给出对象级方案，不提交写入 | 足以支撑结论的平台事实 |

用户没有提供 ID 时，先通过列表和详情发现真实对象；名称不能唯一定位时再请用户选择。用户明确要求新建一套演示时，可以创建新项目和页面，但仍要先确认工作空间及现有资产，避免重复建设。

## 页面源码怎样运行

页面源码不是可以脱离平台随意运行的网页：

1. Backend 保存 Vue SFC 和对象版本，并把项目配置、可见资产和允许的 import 能力组装成受控上下文。
2. Runtime 在项目定义的固定画布中编译和渲染页面，负责主题、字体、资源解析、页面上下文和布局诊断。
3. Backend 收集编译、渲染和布局结果，并把 Job 状态、错误码和诊断返回给 CLI。
4. 智能体依据诊断与截图做局部修正，使用最新版本基线再次提交。

这解释了几个关键约束：

- 页面必须是完整 Vue 3 SFC，不能提交 HTML 片段、Markdown 或说明文字；
- 画布是固定尺寸二维空间，不是可滚动网页；
- 页面只能引用平台当前公开并可见的版本化能力与资产；
- 本地语法正确不代表 Runtime 编译、资源加载和布局校验一定成功；
- 项目 `configuration`、Backend standards、Runtime Kit 清单和真实对象结果优先于模型记忆。

## 开始任务时的判断顺序

1. 判断用户想要的是平台内成果还是独立文件；只有前者使用本 Skill。
2. 判断是新项目、多页任务、单页任务、共享资产任务，还是只读分析。
3. 解析当前 Profile 和工作空间，再发现或确认目标项目与页面。
4. 读取项目配置、路由、现有页面和相关共享资产，形成内容 brief 与对象变更清单。
5. 按任务继续读取页面生成、源码、组件、资源或交付参考，然后使用当前 CLI 帮助和 Backend Schema 执行。

不要因为用户只描述了内容主题，就跳过平台基线直接写页面；也不要因为平台对象很多，就先创建一整套资产。选择能够满足任务并保持复用价值的最小对象集合。
